General input paramters:
- ITEMAX (Maximum number of iterations of the main loop)
- NPRINT (Debugging parameter of old, can be ignored in most cases, just keep at 0)
- NEWMOD (Decides wether you start a model from scratch (1) or use an old one 0. 0 should be the default for time reasons)
- NOARCH (write out feature. In most cases should be kept at 0)
- JONTYP (Swtich to choose which partion functions are used. Should always be 3)
- MOLOLD (Switch used for quicker convergence by using older stored valous. Should be 1)
- PP/SPH (Choose between plane parallel and sqhperical operation of the code)
- TEFF (Effective temperature the solver should try to achieve. In units of K)
- GRAV (Surface gravitiy of the simulated object. In units of Log g)
- MODEL (Can be used to give a headline in the output file. Also round-trips through the binary .arciv archive/restart file -- unlike most other cosmetic-label parameters, this one can't be casually removed without also handling the archive format.)
- M/MSN (Mass of the irradiated object when sphercial mode is chose, in solar masses)

Convection related input parameters:

- NOCONV (Number of first layers for which convection should be ignored. Counting from the top.)
- XMAX (scales absorption that is used for the rossland mean opactiy. Probably keep at current value)
- TAUM (Parameter used to distinguish at which optical depth, the core and the surface of the star lies.)
- AMLOSS (Scales the mass loss for a stellar atmosphere. Potentially useful in the future. Currently keep at value its set to.)
- LINCIA (Switch to enable (1) or disable (0, default in every existing .input file) CIA
          (collision-induced absorption). When enabled, MARCS reads its active pair list
          from a fixed path, ./data/cia_list.dat, which is not created automatically --
          see the "CIA" section in README.md for the file format and how to build one from
          data/cia_pairs_all.dat. Zero I/O and zero effect on a run unless explicitly set to 1.)
- MIHAL (Parameter that sets the lowest layer for which radiative equilibrium will be used. For Layers below flux constancy will be assumed.)
- KONSG (For 0, no real impact on the simulation. For 1, radius and gravity can get varied. Usual value is 0)
- KORT (Used to change between different ways of how the maximum temperature change is applied. For 0, temperature limitation is ignored. For 1 ... For 2 ... For 4 and 5, maximum change is equal to exactly KPP. For 6, its similar to 4 and 5 with some additional calculations. For 7, same as 6 but its correction floor resets whenever chemistry recalculates -- meant for ABUNDF=ITEMAX.)
- KPP (input-deck label only -- the actual Fortran variable it's read into is TDIFF, not any variable named KPP. Genuinely live: caps the per-iteration temperature-correction step size in the period-2 limit-cycle damper. Maximum temperature change allowed. Expects a, at maximum 3 digit, integer. Usually one should choose a single digit integer.)
- TCONV (Convergence temperature. If the wanted change by MARCS is below this temperature, the simulation is converged)
- dpein (Determines the derivate stepsize in solve for the electron pressure. Keep low.)
- dtin  (Determines the derivate stepsize in solve for the temperature. Keep low.)
- METPE (Parameter which switches between the old method of calculation the electron pressure (1) and the new (2). For temps below 1500 K choose the new)
- PALFA (Mixing length ratio for convection. Default to 1.5 (Gustafsson 2008 Chapter 3.2))
- PBETA (Turbulent pressure scaling factor (Gustafsson 2008 Chapter 3.1). Usually 0 in cases where turbulence plays a small role. )
- PNY (Factor for convection calculation (Gustafsson 2008 Chapter 3.2 and Henyey et al. 1964). Default value is 8)
- PY (Factor for convection calculation (Gustafsson 2008 Chapter 3.2 and Henyey et al. 1964). Default value is 0.076)
- VFIX (Swtich that at 0 speeds up with some velocity calculations otherwise some calculatons are scaled by what is set at VFIX. Default value 0)
- MYPNTS (input-deck label only -- the actual Fortran variable it's read into is MMY, not any variable named MYPNTS. Genuinely live: number of Gaussian-quadrature integration points, used directly in CALL GAUSI(MMY,...). Typical decks use 4, not 1.)
- NCORE (Realted to spherical models. Ignore in PP case. Number of rays for raytracing of the in the core. Default 5, but honestly I dont know.)
- KDIFF (Genuinely live, despite older docs calling it "probably deprecated" -- feeds a real calculation, TAURAT=10.**(0.1*KDIFF-0.01), which affects spherical-mode ray tracing (via /CSPHER/ storage-association with TLIM). Ignore in PP case.)


- ABUNDF (Integer number that determines how often are abundances updated. Setting it to a number X means only every X-th iteration updates the abundances. Useful for models that oscillate and speeds up convergence. Special case: ABUNDF=ITEMAX only calculates abundances at the beginning and when the RT is converging.)

Irradiation related input parameters:

- IRRAD (Switch to turn on irradition by another star.)
- STEFF (Effective temperature of the irradiating star. In units of K.)
- RSTAR (Radius of the irradiating star. In units of solar radii.)
- SMAJOR (Distance of the irradiating star. In units of A.)
- FACTOR (Heat redistribution factor. See Eq. 3.1 in Azzurra d'Alessandros PhD thesis)
- SPECTR (Switch to have the code use and input spectrum as input)
- SPECSC  (Scaling factor for the incoming radiation for spectrum. Useful for slowly converging a model or to model stellar evolution effects.)

Surface related input parameters:

- SURFAC (Switch that turns on the surface module (1). Default 0.)
- TSURF (Sets the desired surface temperature in K. Genuinely live -- feeds directly into the temperature-anchor residual RT(K)=-(TT(K)-tbottom).)
- ALBEDO (Sets an albedo of the surface you are modelling. 1 full reflection resulting in doubling of the flux overall. 0 meaning no extra flux from the surface. Genuinely live -- feeds directly into the reflected-flux term Pstar(JTAU)+=reflect*Pstar(JTAU).)
- NCH4 (Switch that determines wether or not the opacity calculation of CH4 should be done in a step by step approach. Helps with convergence if CH4 is an issue. Default is 0)

VIRGA related input parameters:

- VIRGA (Switch to turn on (1) or off (0) the VIRGA cloud-opacity coupling, via a python3 subprocess call. Confirmed live but missing from earlier versions of this doc -- add here rather than assume it doesn't need documenting. Read on the same line as CNDNSA/CLOUDS/LATENT below, all three only meaningful when VIRGA=1.)
- CNDNSA (Live: depletes gas-phase elemental abundances by what virga
          condenses, via a second GGChem pass whose result (ppallmol/
          ppallat/ggmu/ggrho/ro/ppel/etc) now feeds KROME/opacity/the
          rest of the model for this cycle. Pre-depletion seed values
          kept in ppallmol_cond/ppallat_cond; see cndnsa_diag.dat.)
- CLOUDS (Governs creation of x_virga/s_virga, virga's cloud opacity --
          not yet merged into OPAC's X(K)/S(K), so currently has no
          effect on the model either way.)
- LATENT (Live: adds a cloud-condensation heat term FFL(k) into the
          flux-constancy/Stromgren equations in SOLVE, alongside the
          existing convective flux FFC(k). See ffl_diag.dat.)

The noneq input parameters are:
 - NONEQ (Basic on/off switch for non equilibrium chemistry. Expects a numeric value of 0 (off) or 1 (on))
 - PHOTO (Basic on/off switch for including photo rates. Expects a numeric value of 0 (off) or 1 (on).
          currently only able to turn on/off the photolysis module for ozone with more potential features later)
 - phSCAL(Factor that scales the inensity of the radiation that the photo chemistry works with. Quick and easy parameter
          to either increase or decrease the impact of the photo chemistry. Expects a Value in the format of X.XE+/-XX)
 - INITAB(Flag to turn on or off the use of initial abundances for the KROME runs)
 - INITMD (Init Mode for KROME's non-eq chemistry, read right after INITAB=
           on the same line. Default 0: resets to GGchem/init every
           chemistry call. 1: resets once, then each call continues from
           the last state (needs krome_solve's own MIXRESCALE/MIXAPPLY
           machinery to behave). Formerly the namelist variable `initmd`
           in &outlist -- moved here 2026-10-20 to sit with the rest of
           the noneq-chemistry switches instead of a separate namelist.)
 - DTMIN (Starting timstep for KROME in seconds. Expects a Value in the format of X.XE+/-XX)
 - DTMAX (Maximal timestep size for KROME in seconds. Expects a Value in the format of X.XE+/-XX)
 - tMAX  (Final time the network will be solved for in seconds. Expects a Value in the format of X.XE+/-XX)
 - DTINC (By how much the starting timestep should increase every iteration until DTMAX is reached. Expect a value in the format of X.XX.
         Usually it is advised to have some increase or choose starting timestep and final time wisely to not have your calculation run for too long.)
 - KDEBUG (Switch that when turned on (set to 1) writes out a lot of extra data
           arrays which can be useful for debugging or understanding the
           physics better -- and this is real, non-trivial I/O: it gates a
           per-wavelength write inside the main flux loop (BPL_sun.dat,
           BPL_upper.dat, XJ_upper.dat, XJ_lower.dat -- one line per
           wavelength point per outer iteration) plus a per-KROME-timestep,
           per-layer dump to krome_full_output.dat. Cost scales with the
           wavelength grid size and iteration count, so this is not free to
           leave on for a full production run. Usually keep it at 0.)
 - KROMER (CORRECTION 2026-08-20: earlier notes here saying this is a
           confirmed no-op were WRONG -- an incomplete grep missed the real
           usage. It IS a genuine, live on/off switch: at
           marcs.f:14619 `if (krome_return == 1)` gates whether KROME's
           computed number densities are actually copied back into MARCS's
           num_den_at/num_den_mol/ppallmol/ppallat/krome_not_pp arrays (which
           feed the rest of the model downstream). With KROMER=0, KROME still
           runs and integrates the non-eq chemistry every iteration, but the
           results are silently discarded -- never fed back into MARCS. This
           is exactly a "debug the non-eq chemistry in isolation, disconnected
           from the rest of the code" switch. 0 is off (isolated/no feedback),
           1 is on (results used).)
 - CNVCRI (conv_crit in the code. Controls per-layer KROME chemistry integration
           length. 0 = always run full tMAX. Nonzero = min(vert_mix_time, tMAX),
           plus this is the early-exit convergence magnitude threshold (see
           CNVRAT below).)
 - CNVRAT (conv_rate in the code; read right after CNVCRI= on the same line.
           Rate-of-change threshold [1/s] alongside CNVCRI's magnitude check;
           default 0 disables it. Exit also needs 3 consecutive passes. Formerly
           the namelist variable `conv_rate` in &outlist -- moved here
           2026-10-20 to sit with the rest of the noneq convergence criteria.)
 - MIXING (mixing_on in the code; read right after CNVRAT= on the same line.
           Switch for krome_solve's vertical eddy-mixing pass (DECOUPLE/
           MIXRESCALE). 0 (default, blank-safe) = off, 1 = on. Only
           meaningful when NONEQ=1. Replaces the old hardcoded
           mixing_enabled compile-time constant -- 2026-10-21.)

Optical depth related input parameters:

 - LOGTAU (Parameter that determines the range optical depth for which the atmosphere should be simulated. Expects values that are exponents to the power ten. You need to provide at least two values
           one starting value and one final value.)
 - DIFFER (Value that determines by how much of LOGTAU a atmospheric layer should change.)

Namelist input parameters (read via Fortran NAMELIST blocks, &name ... &end,
rather than fixed-column fields -- easy to miss since they don't look like
the rest of the file):

 &abundances namelist:
 - zscale (Metallicity scale factor relative to solar -- genuinely important,
           applied to every element's abundance except H/He. Not cosmetic.)

 &inputos namelist:
 - losresl (If 1, the OS wavenumber grid is computed based on a specified
            spectral resolution (osresl) instead of fixed steps. Genuinely live.)
 - osresl (Spectral resolution used when losresl=1. Genuinely live.)
 - wnos_first (First wavenumber of the OS grid. Genuinely live.)
 - wnos_last (Last wavenumber of the OS grid. Genuinely live.)
 - kos_step (Number of fixed steps used when losresl=0. Genuinely live.)

 &outlist namelist:
 - masslinf (Genuinely live -- gates real behavior, IF(masslinf.eq.0) GO TO 4001.)
 - pecap (TRYCK/TRYCK_sph electron-pressure step cap, opt-in, off unless set
          .true. -- helps oscillating/non-converging high-Z runs, can silently
          truncate an otherwise-converged PPE(K) on runs that don't need it.)
